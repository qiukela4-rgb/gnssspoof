## 四、待你执行的清单

### 准备

- 一台 Android 12+ 且已 Root（Magisk / Kitsune）、Zygisk 已启用、装了 LSPosed 的手机
- `adb` 可用（`D:\tools\android-sdk\platform-tools` 里就有）

### 步骤

1. **装包**（debug 包自带签名，可直接装）

   ```
   adb install -r app\build\outputs\apk\debug\app-debug.apk
   ```

2. **在 LSPosed 里启用**
   - 打开 LSPosed → 模块 → 勾选 **GnssSpoof**
   - 作用域：**只勾「系统框架」**。勾任何 App 都可能触发反注入检测
   - 重启手机

3. **验注入**（这步最关键）

   ```
   adb shell getprop | grep gnssspoof
   ```

   应当看到：

   | 属性 | 期望值 | 说明 |
   |---|---|---|
   | `injected` | `1` | 模块进了 system_server |
   | `hooked1` / `hooked2` / `hooked3` | `1` | 三条通道都挂上了 |
   | `const_ok` | `12/8/15` | 反射读到了编码常量 |
   | `const_err` / `provider_err` / `hookerr*` | **不应出现** | 出现即说明对应环节失败，把它的值抄下来 |

4. **验功能**
   - 打开一个能看卫星数的 App（GPS 状态类工具、或直接用跑步软件）
   - 期望：显示 **8 颗 GPS** 卫星，信噪比在 32–38 之间
   - 再看一眼属性：`replaced` / `push` / `w2p` 的时间戳应当随使用变化

5. **把结果告诉我**
   - 第 3 步的完整 `getprop` 输出（有多少贴多少）
   - 第 4 步看到的卫星数截图

### 如果没生效，先看这三个属性

| 现象 | 大概率原因 |
|---|---|
| `injected` 都没有 | 作用域没勾「系统框架」，或没重启 |
| `hooked1/3` 缺、`provider_err` 有值 | 该 Android 版本的 `GnssStatusProvider` 类名或方法变了 |
| `hooked2` 有但卫星数仍是 0 | `writeToParcel` 的 Parcel 写了但被上游覆盖，属于 `writeToParcel` 钩子的已知隐患 |
