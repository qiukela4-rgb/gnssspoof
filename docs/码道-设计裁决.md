## 一、【必须改】48 项基线表的「编号编码」列，8 行错 7 行

`design.md` 第 430–437 行的基线表，编码列只有 i=0 是对的，其余 7 行全部错。
你把卫星号的移位数与星座标识的移位数**对调**了。

| i | 卫星号 | 你写的 | 实际含义 | 正确值 |
|---|---|---|---|---|
| 0 | 1 | 0x110F (4367) | ✅ 凑巧对 | 0x110F (4367) |
| 1 | 2 | 0x120F (4623) | svid=1、星座=2 | **0x210F (8463)** |
| 2 | 3 | 0x130F (4879) | svid=1、星座=3 | **0x310F (12559)** |
| 3 | 4 | 0x140F (5135) | svid=1、星座=4 | **0x410F (16655)** |
| 4 | 5 | 0x150F (5391) | svid=1、星座=5 | **0x510F (20751)** |
| 5 | 6 | 0x160F (5647) | svid=1、星座=6 | **0x610F (24847)** |
| 6 | 7 | 0x170F (5903) | svid=1、星座=7 | **0x710F (28943)** |
| 7 | 8 | 0x180F (6159) | svid=1、星座=8（非法值） | **0x810F (33039)** |

**错在哪**：你算的是 `(1 << 12) | (svid << 8) | 0xF`，正确是 `(svid << 12) | (1 << 8) | 0xF`。
`i=0` 时 `svid=1`、`constellation=1` 数值相同，把移位颠倒这个错误盖住了——所以第一行对，后面全歪。

**有个巧合可以自查**：你表里 `0x150F` 出现在 svid=5 那行，但 `0x150F` 的真实拆解是
「svid=1、星座=5」。位置和含义正好错位，这本身就是错位的证据。

**若照错表实现，后果不是"数字不好看"，是功能坏掉**：

- 系统读 `svidWithFlags` 时取 bit12 以上作卫星号 → 8 颗全部解析成「1 号卫星」，重复 8 次
- 取 bit8–11 作星座 → 得到 1..8，而合法星座只有 1–7（GPS/SBAS/GLONASS/QZSS/BEIDOU/GALILEO/IRNSS），第 8 颗非法
- 结果比原实现更差：App 看到「8 颗信号但编号全是 1 且有一颗星座非法」

**要求**：

1. 把 `design.md` 430–437 行编码列改成右侧「正确值」一列，十进制一并改
2. 你的伪代码 `编号 = encode(i+1, GPS, 移位, 标志)` 是**对的**，保持不动——错的只是这张表
3. 改完自己复核一遍：逐行算 `(svid << 12) | (1 << 8) | 0xF`，不要再凭手感

## 三、裁决 2：无效签名配置**不得阻断 debug** —— 你的设计要改

你建议 fail-fast（配置阶段抛 `GradleException`，坏配置让 debug 也失败）。**不接受**，理由三条：

1. **debug 与 `keystore.properties` 无关**。debug 用 AGP 自动生成的 debug keystore，
   那个文件只作用于 release。让无关配置阻断日常构建，是过度耦合。
2. **配置阶段抛异常会让整个项目配置失败**。不只是构建，`gradlew tasks`、IDE 同步、
   任何 Gradle 调用都会失败，排查时拿不到任何有效信息，只能靠猜。
3. **规格 5.3.3.1 的语境是签名配置**，签名只出现在 release。该条的「构建失败」应理解为
   「release 构建失败」，不是「所有构建失败」。

**改成**：

- 配置文件存在且字段完整 → 启用 `signingConfigs.release`，release 产物已签名
- 配置文件存在但字段缺失/为空 → **仅当本次构建包含 release 任务时**抛 `GradleException`；
  纯 debug 构建（如 `build.cmd`、`build.cmd test`）打 warning 后跳过签名，正常完成
- 配置文件不存在 → 跳过签名，release 产出 unsigned（现状，不变）

实现上用 `gradle.startParameter.taskNames` 判断本次是否涉及 release 即可，不要引入新依赖。

**同时**：请把 `spec.md` 5.3.3.1 补一句限定——「（指 release 构建；debug 构建不受影响）」。
规格是你我共同维护的契约，改实现不改规格，下一轮又会绕回同一个歧义。

## 六、附加要求：B2 的测试用例必须能抓住移位错误

你现在定的样例是 `(1, 1, 12, 8, 0xF) → 0x110F`。这条**测不出**移位颠倒——
因为 svid 和 constellation 都是 1，两种写法结果相同。这正是上面那张表能错 7 行的原因。

B2 至少要有一条 **svid ≠ constellation** 的用例。建议补这三条，期望值我已算好：

| 用例目的 | 输入 | 期望值 |
|---|---|---|
| 移位不可对调 | `encode(5, 1, 12, 8, 0xF)` | `0x510F`（20751） |
| svid 边界 | `encode(32, 1, 12, 8, 0xF)` | `0x2010F`（131343） |
| 星座隔离 | `encode(1, 5, 12, 8, 0xF)` | `0x150F`（5391） |

第三条尤其关键：`encode(1, 5, ...)` 得 `0x150F`，与你错表里「svid=5」那格数值完全相同。
如果实现写反了，这条断言会失败；写对了，它同时证明「0x150F 属于星座 5，不属于卫星 5」。

用例名照 `tasks.md` B2-3 的四类覆盖保留，数量从 ≥3 提到 **≥4**，规格 5.2.1.5 的「不少于 3」是下限不是上限。
