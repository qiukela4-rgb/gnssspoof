| 文件 | 变化 |

| `SvTableGeneratorTest.java` | 新增，14 个用例 |

| 删除 | `FAKE_SV_COUNT`、`CN0_BASE` 等 7 个硬编码常量（已被生成器取代） |

生成器的四条规则：

1. **数量**：`svMin + (svMax - svMin) × (0.5 + 0.5·sin(2πt/T))`，周期 180 秒
2. **可见性**：每颗卫星一条独立正弦曲线（4–15 分钟周期），按分数取前 N 颗
3. **仰角**：`acos` 变换实现球面均匀分布，限制 5–85°，叠加 ±0.6° 缓慢漂移
4. **载噪比**：`25 + 18·sin(仰角) ± 抖动`，落在 15–48 dB-Hz；方位角随机起始 + 10 分钟一圈旋转

## 五、三处需要知道的差异

### 1. 室内真实只有 35 颗，我们给 79

使用者说户外跑时校园跑显示 67–80，这个范围对户外成立；但**室内真实只有 35 颗**，79 就偏多了。

**判断**：本模块的使用场景是跑步（户外），58–82 合理。如果想覆盖室内外都能对上，
可把默认调到 `45–70`：

```
adb shell su -c 'setprop debug.gnssspoof.svmin 45'
adb shell su -c 'setprop debug.gnssspoof.svmax 70'
```

### 2. 室内真实只有 3 个星座

室内收不到 Galileo 与 QZSS，我们的伪造把五个都给了。户外五个星座都在，所以这条在跑步场景下不是问题。

### 3. 真实环境「无定位时 CN0 为空」，我们给了值

这是设计取舍：本模块的用途正是「虚拟定位有坐标、但 GNSS 无测量」的时候补上卫星表，
所以必然要给出 CN0。**如果被检测，这一条是最可能被问的地方**——真实设备在无测量时 CN0 确实是空的。

目前没有做「按真实测量状态动态决定是否给 CN0」，因为一旦有虚拟定位，真实测量就没了，
给了才是模块的目的。这条记录下来，等真遇到再说。

## 六、单元测试

```
SvIdCodecTest          7 个用例，全过
SvTableGeneratorTest  14 个用例，全过
```

关键几条：

- `testCn0CorrelatesWithElevation`：皮尔逊相关系数 > 0.6
- `testNoMassiveJumpBetweenFrames`：相邻 1 秒内进出的卫星 ≤ 3 颗
- `testAzimuthRangeAndNotEquidistant`：方位角不得呈等距分布
- `testSvidWithinConstellationLimit`：卫星号不越各星座上限
- `testUsedInFixIsSubset`：参与定位的那批 CN0 不低于其余

做过变异测试：把 `CN0 = 25 + 18·sin(仰角)` 改成常数 `35`，`testCn0CorrelatesWithElevation` 立刻失败，
其余 20 条不受影响——说明测试定位精准，不是摆设。
