## 三、B1：消除「两套伪造数据实现」（最高优先级）

**问题**：同一份卫星参数在 `buildFakeGnssStatus()`（构造 `GnssStatus` 对象）
和 `writeToParcel` 钩子（直接往 `Parcel` 写）里各写了一遍。
以后改一颗卫星的取值，漏改一处，两条通道就会给出不同的卫星表。

**要做**：

1. 把卫星参数的生成集中到一个私有方法，两个通道都调它。
   建议签名（可自行调整，但必须两头共用）：
   ```java
   private static void fillFakeArrays(int n, int[] svidWithFlags, float[] cn0,
                                      float[] elev, float[] azim, float[] carrier, float[] baseband)
   ```
2. `writeToParcel` 钩子改为遍历这套数组写入，不要重复写死数字。
3. 顺手把散落的魔法数字提成常量（`CN0_BASE = 32.0f`、`CN0_STEP = 1.0f`、
   `ELEVATION = 45.0f`、`AZIMUTH_STEP = 22.5f`、`GPS_L1_FREQ = 1575.42f`）。

**验收（WorkBuddy 会逐项核对）**：

- `build.cmd` 输出 `BUILD SUCCESSFUL`
- `writeToParcel` 钩子与 `buildFakeGnssStatus` 里**不再出现** `32.0f` / `45.0f` / `22.5f` / `1575.42f` 字面量
- 改完两条通道写出的数组值与原实现逐项相等（列出对照表，不要只说"一致"）

**汇报格式**：



2. `MainHook` 改为调用它，删掉类内重复实现。
3. 加 JUnit4 单元测试（`app/src/test/java/.../SvIdCodecTest.java`），至少覆盖：
