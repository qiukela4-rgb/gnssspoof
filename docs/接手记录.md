## 四、体检发现（按风险排序，尚未处理）

### 高：同一份伪造数据有两套独立实现

`buildFakeGnssStatus()`（构造 `GnssStatus` 对象）和 `writeToParcel` 钩子（直接往 `Parcel` 写）
各自重复实现了 CN0 / 仰角 / 方位角 / 载频的取值。改一颗卫星的参数要改两处，
**漏改就出现「两条通道给出不同卫星表」**。这是最容易在后续维护中出问题的地方。

### 高：注释与实际数量不一致

`FAKE_SV_COUNT = 8`，但第 80 行注释写「立刻主动把 **16 颗** 假卫星推给它」，
第 152 行写「GPS svid 1..**16**」。以代码为准是 8 颗。注释会误导后来者。

### 中：minSdk 26 与功能实际要求不符

`app/build.gradle` 声明 `minSdk 26`，但依赖的 `GnssStatusProvider` 是 Android 12（API 31）才有的类。
在 26–30 的设备上会安装成功、模块启用、**然后什么都不发生**，也没有任何提示。
README 的「环境要求：Android 12+」只在文档里，构建产物没约束住。

### 中：release 产物无签名

`buildTypes.release` 没有 `signingConfig`，产物是 `app-release-unsigned.apk`。
README 让使用者「自行签名」，实际交付时容易卡在这一步。

### 中：`GnssStatus.wrap()` 属私有 API，跨版本有断裂风险

通过 `XposedHelpers.callStaticMethod(GnssStatus.class, "wrap", ...)` 调用，
这是 `@UnsupportedAppUsage` 隐藏方法，参数表在部分 Android 版本上有变化。
当前在 Android 15 验证可用，但没有版本探测或降级路径。

**建议排期**：下一期处理，具体版本由维护者排期。

### 低：`writeToParcel` 钩子直接写 Parcel 后 `setResult(null)`

在 `beforeHookedMethod` 中先写入再跳过原实现。若上游对同一个 Parcel 还有后续写入，
会因位置前移而错位。目前未观察到问题，属潜在隐患。

### 低：无自动化测试

`encodeSvidFlags()`（svidWithFlags 位布局）是纯函数，完全可以脱离 Android 单测，
但现在和 Xposed 桩耦合在同一个类里，想测只能靠真机。

### 低：诊断属性没有文档

代码里写了 `debug.gnssspoof.injected` / `hooked1` / `w2p` / `push` 等属性用于自检，
但没有任何地方说明怎么读（`adb shell getprop | grep gnssspoof`），排查时无从下手。
